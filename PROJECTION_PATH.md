# Milestone 4.3: projection paths and one NF4 fusion

## Evidence boundary and decision

The user measured `b45a74b` on T4: **677.431 ms original kernels / 46.885 s timed training = 1.445%**. The prior category profile is GEMM 39.82%, copies/dtype 18.77%, elementwise 16.30%, NF4 dequant 4.82%. No raw profile identifies the LM head, q/v, or a particular cast's share in the current run. Those categories have different denominators from the admission gate.

Investigated the installed, pinned sources: Soup 0.77.0, Transformers 5.16.1, TRL 0.29.1, PEFT 0.20.0, bitsandbytes 0.50.2, Accelerate 1.14.0. The following full-size T4 paths/dtypes are **source-derived**, also consistent with the official README. Local execution uses a reduced real Qwen/PEFT model and CPU AMP; no full-size T4 runtime was available. The supplied diagnostic must confirm them on the actual task.

| Candidate | Verified source path / work | Decision and uncertainty |
|---|---|---|
| LM-head forward and input-gradient GEMM | Frozen dense tied weight `[151936,1536]`, token matrix `[B*T,1536]`; forward creates full logits, backward multiplies vocabulary gradients by the weight. No weight gradient. | Potentially substantial part of GEMM, but share unknown. Keep cuBLAS: a custom GEMM needs T4 shape/throughput tuning and accumulation validation. Fusion that suppresses logits would break required metric/rewind consumers. |
| Quantized q/v GEMM plus LoRA | q `[1536,1536]`, v `[256,1536]`, 28 layers; frozen NF4 base plus trainable rank-16 adapters. Dispatch can already use fused CUDA dequant/GEMM. | Keep dispatch and GEMM. Replacing only an existing fallback avoids forcing a slower path where the library already fuses work. |
| Nested NF4 scale reconstruction + dequant | Fallback forward reconstructs scales, adds offset, dequantizes weight, then calls native linear. Backward reconstructs/dequantizes weight for native input-gradient matmul. | **Implemented one shared primitive**: combine the three reconstruction operations in one original Triton kernel. Apply to the four fixed Qwen projection shapes, including MLP and attention projections using the same format. Removes scale intermediates/launches. Speed and optimized eligible share are unmeasured. |
| Broad cast/elementwise replacements | 35.07% combined in the prior profile; includes many unrelated operations. | No safe global interception or unique attribution. Trace shapes/scopes before choosing a specific fusion. |

Efficiently replacing NF4 work may still leave eligible share below 5%. Do not add work or retain redundant intermediates to raise the numerator. The next decision must use new paired measurements and the attributed projection trace.

## Exact setup, forward and backward paths

1. `soup_cli/trainer/sft.py:SFTTrainerWrapper._setup_transformers` builds the quantization config, loads the base, calls `prepare_model_for_kbit_training`, then wires PEFT. `utils/gpu.py:resolve_frozen_base_load_dtype` chooses fp16 on a pre-Ampere T4; `get_compute_dtype` also returns fp16. `utils/quant_menu.py:build_quantization_config_for_loader` selects NF4 and default double quantization. `bf16_fp16_flags` selects fp16 AMP. No settings in these functions are changed.
2. `transformers/quantizers/base.py:get_keys_to_not_convert` excludes output embeddings and tied weights. `Qwen2ForCausalLM.lm_head` is therefore ordinary `nn.Linear`, tied to the embedding. `peft/utils/other.py:prepare_model_for_kbit_training` freezes base parameters and upcasts non-Params4bit fp16/bf16 parameters to fp32. Norms, biases, and the tied head/embedding are fp32 after preparation; packed weights remain uint8. Linear4bit later casts its bias to its compute dtype on first forward.
3. `transformers/models/qwen2/modeling_qwen2.py:Qwen2ForCausalLM.forward` calls `lm_head(hidden_states[:, slice_indices, :])`. The final RMSNorm's fp32 weight promotes its output to fp32. AMP rounds head input and weight to fp16 for native linear, whose logits are fp16. `ForCausalLMLoss` explicitly upcasts logits to fp32; Accelerate's `convert_outputs_to_fp32` also makes returned logits fp32 for TRL metrics and Soup rewind. The native head backward computes the **input** gradient even though its weight is frozen, including the fp16 gradient/cast back to fp32. A frozen head does not justify omitting this GEMM.
4. `soup_cli/utils/peft_wiring.py:resolve_lora_target_modules` delegates Qwen2 auto targets to PEFT's mapping: `q_proj`, `v_proj`. `peft/tuners/lora/bnb.py:Linear4bit.forward` invokes the base, clones its output, runs `lora_B(lora_A(dropout(x))) * scaling`, and adds it. Adapter storage is fp32, rank 16, scale 2, dropout 0.05; AMP handles matrix multiplication. The implementation does not intercept this path or change random-number use.
5. `bitsandbytes/nn/modules.py:Linear4bit.forward` remembers input dtype, casts input/bias to its fp16 compute dtype, calls `bnb.matmul_4bit`, then casts the result back to input dtype. `autograd/_functions.py:MatMul4Bit.forward` passes packed weights and nested-scale metadata to `torch.ops.bitsandbytes.gemm_4bit`. `backends/cuda/ops.py` keeps its original architecture/shape heuristic. For more than 1,536 flattened input rows it uses `_dequant_linear_fallback`; smaller cases depend on that heuristic. Do not assume every q/v forward reaches the fallback.
6. The fallback currently reconstructs nested scales as fp32 `code8[scale_byte] * absmax2[block // 256]`, then adds the fp32 offset, then decodes NF4 weight nibbles using one scale per 64 weights and rounds to the input dtype. The replacement computes exactly that fp16 weight, then calls the same `torch.nn.functional.linear(A, weight, bias)`. The native fused-GEMM branch is untouched.
7. `autograd/_functions.py:MatMul4Bit.backward` invokes `functional.dequantize_4bit(B, state).to(grad_output.dtype)` and native `torch.matmul(grad_output, weight)` when the input needs a gradient. The functional hook supplies the same fp16 weight. Native bias reductions and PEFT adapter gradients remain intact. No quantized-weight or scale gradient is introduced. In the first decoder layer, frozen embeddings can make q/v input gradients unnecessary; later layers propagate gradients to earlier LoRA modules.
8. CE and entropy remain the measured `b45a74b` implementations. Accuracy, label/mask/shift logic, reductions, row-token counts, rewind, optimizer and adapter serialization are untouched. See `LOSS_PATH.md` for those call chains.

## Implementation and bounds

`solution/nf4.py` has one original `nested_nf4_dequant_kernel`. It decodes high nibble first, uses the exact 16 NF4 format constants, reconstructs nested scale indices in blocks of 256, and writes fp16 weights. `enable_fp_fusion=False` preserves separate fp32 multiply and add rounding before the final weight multiply/cast. It allocates no persistent weight cache and performs no extra GEMMs or duplicate dequantization.

`solution.apply()` installs two call-site wrappers for this one operation. Both are idempotent and pinned to bitsandbytes 0.50.2. Guards require CUDA, contiguous uint8 packing, correct tensor sizes/devices, fp32 nested scale/code/offset, NF4 block size 64, and one of `(1536,1536)`, `(256,1536)`, `(8960,1536)`, `(1536,8960)`. The functional path additionally requires fp16 state, a nonnested fp32 secondary state with block size 256, and no supplied output buffer. Transposed packed inputs retain bitsandbytes' transposed-return convention. Other formats, shapes, dtypes, CPU calls and unsupported versions fall back. No global PyTorch primitive is patched.

## Executed verification

- Full solution suite: **73 passed, 4 skipped**, using Torch 2.9.1+cpu, Triton 3.5.1 interpreter, Python 3.12. The four skips are the unchanged starter CUDA-only tests. The new GPU suite should total **77 tests**.
- New format tests compare **exactly** against actual bitsandbytes quantize/dequantize for all 16 NF4 levels, all 256 nested scale codes, a scale-group boundary, tail tiles and full q/v weight shapes. No tolerance relaxation was needed.
- Real `bnb.matmul_4bit` forward/backward tests compare outputs, input and bias gradients exactly. A 2,048-row case specifically checks the real CUDA fallback dispatch when run on CUDA; local CPU execution verifies backward integration, not CUDA forward dispatch.
- A two-layer quantized Qwen + PEFT + fp16 AMP + Accelerate output conversion runs the actual Soup rewind/TRL NLL method chain. It proves nonzero upstream LoRA gradients, compares every trainable gradient, loss/entropy, exact accuracy/token metrics and exact rewind records, with identical dropout RNG in the two reference runs. The head is tied/frozen fp32 with fp32 input, fp16 internal output and fp32 input gradient in this local AMP test. Tiny test shape guards are overridden only by pytest; production has no test flag.
- **79 official regression tests passed** with `SOUP_APPLY_SOLUTION=1`. New kernel compiled offline for SM75, 4 warps, **0 shared-memory bytes**. Source scanner: six original kernels, two excluded starter kernels, no prohibited imports/lookalikes/parse errors. All 19 protected file hashes unchanged.
